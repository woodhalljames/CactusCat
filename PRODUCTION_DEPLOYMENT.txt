4. CLOUDFLARE DNS & SSL
------------------------
DNS records are already configured in Cloudflare (proxied):
  A     cactuscatsoftware.com     > 145.223.126.107  (Proxied)
  CNAME www.cactuscatsoftware.com > cactuscatsoftware.com  (Proxied)

IMPORTANT — SSL/TLS mode must be set to Full (Strict):
  Cloudflare dashboard > SSL/TLS > Overview > Full (Strict)

  Flexible mode will cause redirect loops.
  Full (Strict) is correct because Traefik issues its own Let's Encrypt cert.

If Let's Encrypt cert fails to issue, temporarily set DNS to "DNS only"
(grey cloud), let Traefik issue the cert, then re-enable the proxy.

within 60 seconds, provided DNS is pointed at the VPS.

7. SEEDING CONTENT FROM LOCAL TO PRODUCTION
---------------------------------------------
Blog posts, services, and projects are seeded via Django fixtures + media file copy.

STEP 1 — Dump local data (run on your local machine):

    docker compose -f docker-compose.local.yml exec django \
        python manage.py dumpdata \
            blog services projects \
            --indent 2 --natural-foreign --natural-primary \
            -o /app/fixtures_export.json

This writes the file inside the container at /app/fixtures_export.json, which maps
to your local project root as fixtures_export.json.

STEP 2 — Copy fixture and media to the server:

    scp fixtures_export.json root@145.223.126.107:/root/cactus_cat/
    rsync -avz --progress cactus_cat_software/media/ \
        root@145.223.126.107:/root/cactus_cat/cactus_cat_software/media/

    Note: the media folder will be picked up by the production_media_data volume
    on first run. If the stack is already running, copy into the volume directly:

    rsync -avz --progress cactus_cat_software/media/ \
        root@145.223.126.107:/var/lib/docker/volumes/cactus_cat_production_media_data/_data/

STEP 3 — Load the fixture on the server (SSH in first):

    docker compose -f docker-compose.production.yml exec django \
        python manage.py loaddata /app/fixtures_export.json

STEP 4 — Clean up:

    rm /root/cactus_cat/fixtures_export.json

  5. Optionally add SENTRY_DSN for error tracking


9. ARCHITECTURE OVERVIEW
--------------------------
The stack runs entirely in Docker on the VPS:

  Traefik          Handles incoming traffic, SSL termination, HTTPS redirect
  Nginx            Serves /media/ files from volume; proxies all else to Django
  Django/Gunicorn  Serves the application (4 workers)
  PostgreSQL       Primary database
  Redis            Caching and Celery task queue
  Celery worker    Background tasks (order emails, etc.)
  Celery beat      Scheduled tasks
  Local volume     Uploaded media files stored on VPS disk
  WhiteNoise       Serves static files directly from Gunicorn


10. USEFUL COMMANDS
-------------------
  # Restart just the Django container
  docker compose -f docker-compose.production.yml restart django

  # Stop everything
  docker compose -f docker-compose.production.yml down

  # Push latest code and rebuild
  rsync -avz --progress --exclude='.venv' --exclude='__pycache__' --exclude='*.pyc' \
      /home/james/Desktop/Projects/CactusCat/cactus_cat_software/ \

  # Check all container statuses
  docker compose -f docker-compose.production.yml ps

  # Open a Django shell
  docker compose -f docker-compose.production.yml exec django python manage.py shell

  # Backup the media volume manually
  docker run --rm -v cactus_cat_software_production_media_data:/media \
      -v /root/backups:/backup alpine \
      tar czf /backup/media_backup_$(date +%Y%m%d).tar.gz /media
